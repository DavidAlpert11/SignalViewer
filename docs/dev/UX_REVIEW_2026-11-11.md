# Human-factors review, 2026-11-11

A review of the app as a new user meets it (base: `e2a75a8`, L7). Method: the app was run and used -
the welcome screen, every example, a plain CSV with no units and no template (a motor bench test:
rpm, current, temperature, bus voltage, a setpoint, a state), the ArduPilot example in English and in
Hebrew, at 1440 × 900 and at 1280 × 720. Each finding below was seen on screen, not read from the code.

The patch of this review is deliberately small and stays out of the files of the round in progress
(L8 - L13: `relation.ts`, `RelationPanel`, `layout.ts`, `PlotView`'s menu, `GeoChart`, `objectDetect`,
the CLI). It touches `plots.ts` in one function (`offerRightAxis`); everything else is in files that round
does not list. `CHANGELOG.md` will need a two-line merge.

## What is good (keep it)

- The welcome screen: one sentence of promise, one button, six examples that each show one use.
- One accent colour kept for the cursor; calm chrome; light / dark / RTL done properly, not bolted on.
- Nothing happens without a click, and the app says *why* (*Why?*, trust badges, "points drawn for
  samples"). For engineers this is the feature: they do not use a tool they cannot check.
- The command palette finds signals as well as commands.
- Suggestions are offers (start card, right-axis offer, template strip), never surprises.

## Proposed, not done (the owner decides - each changes a rule or a default)

Ordered by what they would do for "people really use it".

1. **The first minute with the user's own file.** Opening a plain file ends on a white rectangle that says
   "Drag a signal here, or click one in the list". The one thing that would help - *Quick look* - is a chip
   at the bottom-left corner, the farthest place from where the eye is. Proposal: when the tab is empty,
   the view suggestions (the template strip's chips) are shown **in the empty plot**, under the sentence,
   and the strip in the side panel shows only once something is plotted. One place at a time, so §3 holds;
   it moves the 23 e2e references to `.tpl-strip`, hence not in this patch. A smaller step is in the
   patch's last commit (the start card offers *Quick look* when no template fits) - drop that commit if
   the larger change is preferred.
2. **"What do I do now?" after the plots are up.** The three things engineers come for - *compare two
   runs*, *find where it went wrong*, *make a report* - are five icons in the rail with one-word labels.
   A first-use hint on each (one sentence, shown once, like the strip's line) costs nothing; better: the
   start card's second line names the next step for *this* file ("2 files open → Compare", "a flight log →
   3 findings", "a golden run exists → Judge it" - the last two exist).
3. **A cursor that is on from the first click.** The cursor is off until `Space`; a new user clicks a plot
   to read a value and nothing happens (hover shows values, but they vanish when the pointer leaves).
   Proposal: the first click on a plot places the cursor (as oscilloscopes and every flight-log viewer
   do); `Space` still hides it. Changes a default many tests rely on.
4. **The status bar speaks the app's language, not the user's.** "3,840 points drawn for 12,300 samples"
   is a trust statement, and a good one, but it reads as a debug line. Proposal: "Every sample shown" /
   "Shown reduced (min-max) - zoom in for every sample", the numbers in the tooltip.
5. **Two cursors: the labels collide** with event texts ("Vibration compensation OFF") and with the
   floating *Note · Find similar · What changed?* bar. Give the bar a fixed place (the plot's head, right
   of the legend) while two cursors are on.
6. **The tab bar's badge "8"** (more tabs of the template) explains itself only on hover. "+8 views" as
   text, or the count inside the menu's first line.
7. **Command palette, empty query:** a flat list of 25 commands; `Next event ]` / `Previous event [` have
   no icon and their key is glued to the label. Recent commands first, then groups with headers; keys in
   the keys column.
8. **Flight logs repeat the group in every row** (`ATT ▸ ATT.DesRoll, ATT.Roll…`) while a CSV's groups do
   not (`motor ▸ rpm`). If deliberate (ArduPilot users say "ATT.Roll"), the group part could be dimmed.
9. **The 3D view's labels pile up** at the default zoom (mode names and event texts on one spot). Declutter
   by priority (object name > mode > events), as the 2D map's timeline already does.
10. **An altitude of -158 m in the copter example's data box** (AGL +41 m): correct data, alarming first
    impression. This is I1 of the 2026-11-10 ideas (altitude datum) - one more reason to do it first.

## Beyond the screen - what makes an engineering tool spread

- **A result to send.** People adopt a viewer when a colleague sends them something made with it. The
  HTML report and the standalone map (L11) are that; a *Copy link to this moment* / "Send this view" (a
  session file small enough to mail, opening on the same cursor) would close the loop.
- **The second file.** The first file shows the app; the second one (yesterday's run, the simulation)
  is where it earns its place. After a first file, *Open another to compare* in the Files panel's empty
  space is the cheapest pointer to the app's strongest feature.
- **A 60-second path per audience** on the docs' first page: "I have a .bin", "I have a .mat from
  Simulink", "I have a CSV" - three clicks each, a picture of the end state.
- **File association and drag-on-icon** in the Windows installer (`.bin`, `.ulg`, `.tlog`): double-click
  a log → the health check. The fastest way to become the default.
