# Signal Viewer – a fresh-eyes review (2026-11-16)

A review, not a fix round: no app code was changed. Done by using the app as a new user would (the
welcome screen and its demos, then real workflows), driving a headless Chromium against
`python run.py --build --port 8766` with the examples in `examples/`. Screenshots: `review_2026-11-16/`.

The owner's guiding remark during the review: *the user is a human – things must be clear, visible and
simple to understand.* The findings below are judged by that yardstick first.

**Caveats.** Headless Chromium, 1440×900; the 3D view on software WebGL ("Reduced quality", no sky or
shadows), so 3D visuals are judged loosely. Not exercised: live MAVLink / Python push / a followed
file, PDF / Word export, video, templates saved by hand, the 2D map's Story in depth.

---

## 1. Verdict in short

The engine is strong: fast, careful with data, broad, and well tested (quick_check green: tsc, 257 Vitest,
backend pytest, mypy; the synthetic benchmark meets every target). Several analysis features are
genuinely excellent – *What changed?*, Align time, Sweeps' results.

The weak side is **what a person sees first**. The demos open, but some of them do not show what their card
promises; a few verdicts on screen disagree with each other or with the CLI; and the screen carries many
small, cryptic labels and overlapping notices. The next round should be about clarity, not features.

## 2. Severe – a wrong verdict on screen

### S1. The pump demo says *Checks: 0 failed*; its own checks file fails 2 of 4
- Steps: Welcome → *A pump on a test bench*. Look at the pill above the plots, then rail → Checks.
- Seen: `Checks: 0 failed · 6 to look at`; the Checks panel: *No limits set on this file's plotted signals*
  (only the gap is listed). Screenshot `01_bench_checks_0_failed.jpg`.
- The same file in CI: `signalviewer-cli check examples/bench/pump_run_07.parquet --checks examples/bench/checks.json`
  → **FAIL** motor temperature (86.3 °C > 85, 30 times from 546 s), **FAIL** pressure (21 bar > 16 at 412 s), exit 1.
- Why it matters: the welcome card promises "a gap and a spike – Checks finds them"; the README says the
  pump runs over its temperature limit. A user sees a green-sounding "0 failed" on a run that fails. The GUI
  has no way to load a `checks.json` (only `app/checks.py`, the CLI, reads it), and the 0.2 s pressure spike is not
  flagged by data quality either.
- Expected: one verdict for the GUI and CI. Either the demo opens with its limits (a template, or the
  `checks.json` next to the file offered on open), or "0 failed" reads "no limits set" when nothing was checked.

No crash, data loss or wrong plotted value was found.

## 4. Weak – clarity for a human (the owner's yardstick)

1. **Cryptic one-letter labels on the stage bar.** `X` (link time axes) and `Zoom: X` (what a drag zooms)
   are the most used controls and read like a close button and a typo. The tooltips explain them; the
   screen does not. Same family: `15/11 9` beside each file (date and signal count, unlabeled), `Files 18`
   (18 is signals, not files), `+8 views`, `!1`.
2. **Instructions as running text above the plots.** "Click: pick · Ctrl or Shift+click: add (same row: or ·
   another row: and) · double-click: zoom" is permanent, dense, and truncated on a narrower window.
   Teach once (the tour / a first-time hint), then hide.
3. **Toasts cover the data.** Two notices stack at the bottom-left over the last plot (and over the map's
   Vehicle box) for several seconds after every demo (`04_toasts_and_cryptic_bar.jpg`). "Text read as
   states: FlightMode" is not something a newcomer needs to read at that moment.
4. **The demos do not say what to do next.** *Find out what went wrong* opens three Compare tabs; the
   Investigate panel and its first step (put two cursors around 38.4–39.3 s) are left to the user to find.
   Each demo could open with one sentence: "Here: the roll leaves its set point three times. Press D and put
   the cursors around the first bump, then *What changed?*".
5. **Two lines of the same run look alike.** A (blue) and B (teal-green) are hard to tell apart at line width,
   especially where they overlap (Investigate, Compare). In the Roll / DesRoll pair the set point (blue
   dashed) hides under the measurement.
6. **The Map bar is long.** Camera Free / On the object, the object chooser, + − fit, Profile, Story, Data,
   Display, Measure, Time Shared / Own time – 14 controls; with the Inspector open it wraps to two rows over
   the map. The new camera itself is clear (two words, a hint line "drag to turn around the object · wheel
   nearer or further, all the way onto it"). When sitting on the object the flight display, the position
   readout and the name label crowd the lower right; the label text has a double outline.
7. **Two ways to make the same offline page.** Report panel: *Make a replay page…* and *Create interactive
   HTML* are described in almost the same words (one page, offline, plots + map + 3D move together, Play).
   Against the project's own rule "one way to do a thing".
8. **Generic product, domain words in the chrome.** Opening a plain CSV shows "**ArduPilot** · Flight on the
   map: 1 tab, 1 plot opened". CLAUDE.md wants domain content only in profiles / templates.
9. **Areas look like three apps.** Recordings has icon buttons and undo in the top bar; Sweeps has
   `Open ▾ Study ▾ Clear ▾` text menus and its own undo row; Fleet uses unstyled native selects.

## 5. Good – keep

- **Speed.** A 632 MB CSV (5 M rows × 7) opens in 2.0 s, 0.05 s from the cache. The synthetic benchmark
  (`--samples 2000000 --check 3`) meets every target: zoom of 30 signals 16 ms, live append 32 ms.
  "Shown reduced (min–max) – zoom in for every sample" is an honest status line.
- **What changed?** (Investigate): the ordered list (Wind −0.38 s, Vibe_Z, Motor3…), *who leads whom* with
  lags, and the same moment in the other run – the answer of the tutorial, in one click
  (`06_what_changed_good.jpg`). The phrase "Leading is not causing" is exactly right.
- **Align time**: finds −104.369 s by correlation, says *reliable*, explains the reference, offers Undo.
- **Compare**: every shared signal ranked, with a small curve of where they differ.
- **Sweeps**: the 1-2-3-4-5 steps (Data, Columns, Goal, Results, Next runs), "12 of 45 sets hold", the best
  set with *Open it* – a clear story.
- **Robust to bad files.** Empty, header-only, damaged .mat / .parquet, ragged CSV: no crash, a short
  message for each ("The file has a header row but no data rows."). A European CSV (`;` and decimal
  comma) reads right. A truncated .bin opens what it can.
- **Formulas are safe** (`__import__`, attribute access, dunders refused by the AST whitelist).
- **Undo / redo / autosave**: Clear all plots → Ctrl+Z → Ctrl+Y, then a reload restores the workspace
  ("Restored your last workspace").
- **Hebrew and dark**: the RTL mirror is complete and the time axis stays left-to-right, as it should.
- **Ctrl+K** finds commands and signals ("align", "roll", "report").
- **The ArduPilot summary line** (max altitude, max speed, battery used, lowest voltage) and the mode band
  above the plots are what a flight engineer looks for first.
- **Tests and checks**: quick_check all green; 89 e2e files; the CLI returns exit 1 on a failed check.
